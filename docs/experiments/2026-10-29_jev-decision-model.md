## 무엇을 시험했나

규칙 파서가 어려워하는 판단을 선택형 질문으로 바꿔 소형 로컬 LLM에 묻고,
텍스트를 생성하지 않은 채 **선택지 번호의 다음 토큰 확률만 읽는** 방식(LLM-as-Jev)을 평가했습니다.

- 모델: Qwen2.5-1.5B-Instruct Q4_K_M (파일 1.04GB, Apache 2.0)
- 실행: llama.cpp CPU 빌드(b11972), `127.0.0.1` 전용 서버, Python은 표준 라이브러리만 사용
- 환경: Ryzen 5 3500(6코어), RAM 8GB
- 데이터: 가상 업무 메시지 28건 (기준일 2026-10-29, 실존 인물·기관 아님)

## 결과

| 판단 | 규칙 파서 | 결정 모델 | 판정 |
|---|---|---|---|
| 업무 메시지인가 | 57% | 82% | 효과 있음 |
| 마감일 선택 (날짜 2개 이상) | 50% | 83% (5/6) | 효과 있음 |
| 내 몫의 업무인가 | 93%* | 7~13% | 사용 불가 |
| 업무 건수 | 67% | 13~20% | 사용 불가 |
| 내 투두에 올릴 것인가 (최종) | 54% | 50% | 개선 없음 |

\* 규칙은 항상 '내 업무'로 간주하므로, 정답 대부분이 '내 업무'인 이 데이터에서 높게 나옴

- 호출당 평균 0.8~0.9초(최대 1.5초), 메시지 1건당 질문 3~4회 → 약 3초
- llama-server 최대 메모리 약 1.8GB
- 수신자 질문은 **위치 편향**: 선택지 순서를 뒤집어도 15건 모두 2번 선택 (내용 판단 불가)
- 종류 판단에서 신뢰도 0.7 이상(68%)만 자동 처리하면 그중 89%가 정답 → 신뢰도 기반 '검토 대기함' 구조는 유효
- 한계: 표본 28건, 같은 데이터로 질문 문구를 1회 조정함

## 재검토 시 참고

1. 사내 LLM(에이전트 플랫폼 등) 사용 가능 여부와 호출 방식(사내망 API 등)을 먼저 확인
2. 사내 LLM이 있으면 '업무 메시지인가', '마감일 선택' 두 질문부터 적용하고, 신뢰도가 낮은 건은 검토 대기함으로 보냄
3. '내 몫인가', '업무 건수'는 더 큰 모델이 필요하거나, 규칙(사용자 이름·직급 지목 여부) + 검토 대기함으로 대체
4. 익명화한 실제 메시지 100건 이상으로 재평가
5. AI 없이도 가능한 규칙 개선(대화 시각 오인, '다음 달 N일', '이번 주 내로', 'N시 반', 주말 보정, 단순 응답·완료·취소 필터)은 별도로 진행 가능
